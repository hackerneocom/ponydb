# remote-pager

一份不可变快照之上的私有写时复制文件。SQLite 看到的是普通的按字节寻址文件。远程存储只在这个候选实际读取的页上被访问，冻结时返回即将发布的完整页。

## 用途

一条 SQL 语句必须针对数据库的一个固定版本运行，然后要么丢弃写入，要么把脏页交给 `versioned-store`。这个分页器就是那一层私有状态。它不上传任何东西。发布是更后面的步骤，发生在 SQLite 完成本地提交之后。

## 工作原理

### 快照

`Snapshot::read_exact_at` 返回一个不可变版本中恰好被请求的字节。缺失的对象是 I/O 错误，不是文件结束。`CowFile::new` 要求页大小为 512 到 65536 字节之间的 2 的幂，并且基线长度是该大小的整数倍。

### 写时复制文件

`CowFile` 保存基线长度、高水位 `base_limit`，以及一张脏页表。读取时如果已有脏页，就从脏页复制。否则从基线填充到 `base_limit` 为止，其余视为零。只有逻辑文件在调用方缓冲区内部结束时，才报告短读；该缓冲区中未读到的尾部为零。缺失的基线页不会被变成零。

写入会算出它将触及的每一页，包括写过当前末尾而产生的空洞。它先加载这些页。如果远程读取失败，或者新页会超过 `max_dirty_bytes`，页表和长度保持不变。只有每一页都暂存完成之后，文件才安装它们并延长长度。

截断缩短逻辑长度，并丢掉新末尾之后的脏页。最后一页的不完整部分被填零。`base_limit` 降到新长度，因此被切掉的字节在文件再次增长时不会重新出现。增长文件就是在新的最后一个字节处写入一个零，从而把空洞物化成脏页。

`freeze` 要求长度按页对齐。它把文件标为已冻结，移出脏页表，并返回 `FrozenPages`：页大小、最终文件大小，以及每个脏页的完整后像。之后对逻辑文件的读取只能通过返回的页表使用这些镜像；进一步写入以 `Frozen` 失败。

### 同步桥接

SQLite 的 VFS 回调是同步的，快照则位于异步对象存储上。`bridge` 把两边拆开：

- `BridgeSnapshot` 实现 `Snapshot`，运行在数据库工作线程上。`read_exact_at` 检查请求截止时间，先查一个很小的精确范围缓存，再在容量为 1 的通道上 `try_send` 一次读取。它以 10 毫秒为一段等待同步回复通道，并在每段之间重新检查截止时间。通道饱和是 I/O 错误，而不是一条无界队列。
- `BridgeServer::serve` 运行在 Tokio 上，不运行在正阻塞于 `read_exact_at` 的工作线程上。它执行 `AsyncSnapshot::read_at` 并把字节送回。丢弃该 future 会取消正在进行的读取。

`versioned-store` 中的 `StoreSnapshot` 是生产环境的 `AsyncSnapshot`：在一次读取的生命周期内，它的长度和字节固定于一份清单。

## 运行诊断

trace 记录页读写完成与桥接缓存命中、未命中、填充和淘汰，不检查页正文；请求汇总分别统计 pager 访问和远程快照页读取。 库不安装全局 subscriber。
